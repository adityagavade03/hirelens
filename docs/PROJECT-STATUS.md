### Earlier audit defects corrected — 5 October 2026

1. **Finalized feedback is protected.** Answer overrides, notes and answer assessments now recheck permissions and finalization under the same report lease used by finalization. Edits return 409 until an authorized reviewer reopens the report. Completed but unfinalized reviews remain editable; new-round history stays locked.
2. **Late provider results cannot change completed evidence.** Code execution runs outside database locks, then takes a short report lease and rechecks the live session before saving. Results arriving after completion return 409 and are not inserted. Delayed AI feedback cannot change finalized reviews; adaptive feedback cannot arrive after session end. Report generation also rejects changed evidence and finalized reports before saving.
3. **The HR editor now refreshes saved candidate drafts.** The API flattens Mongoose Maps so drafts survive JSON serialization. The read-only editor uses each refreshed snapshot; candidate local edits stay separate. HR code and execution history refresh every eight seconds. The UI identifies selected-language saved code, polling, missing drafts and refresh errors. An isolated real-browser check confirmed a new candidate draft appeared without reloading.
4. **Completion/lock edge cases are covered.** ObjectIds normalize to lowercase so alternate casing cannot bypass a report lease. Retrying completion of an old round does not mark a newer scheduled round complete or send duplicate completion notifications.

The original two finalization failures were reproduced before repair. The permanent `tests/finalization.test.ts` contains 14 passing regression tests, including delayed synthetic providers, lease collisions, uppercase IDs, later-round retries and assigned-HR draft access. Test data belonged only to temporary databases. No real provider execution or hiring decision was invented.

## Walk through the intended flow

1. Company creates a job, including difficulty and interview criteria, and sends an HR request. No candidate or shortlist is required first.
2. Candidates fill in profiles (including preferred roles and years of relevant experience), upload PDF resumes, and apply. Each application keeps its submitted evidence.
3. New applications enter automatic LLM screening. Candidates whose validated overall score meets the saved threshold are shortlisted, including candidates with confirmed gaps in required skills. Gaps reduce the score and remain visible for HR review; uncertain, conflicting or truncated evidence stays Under Review. HR accepts the job to review applicants and schedule shortlisted candidates. Company allocation is optional. HR cannot take over another interviewer's candidate without reassignment.
4. HR schedules a private interview directly or selects a batch from job details. A batch produces separate, consecutive appointments and in-app links. It is not a shared group video call. Later rounds remain individually scheduled after the previous round is finalized.
5. A human session combines WebRTC, questions, coding and consented browser/face event monitoring. An AI-assisted session offers an interview plan and adaptive questions after submitted answers. A question can be read aloud using browser speech synthesis; recorded answers require configured transcription and candidate review.
6. Code execution uses Judge0. Submission history stores real provider results; editor snapshots record development at most once per 15 seconds, up to 300 per session.
7. Completion creates a report. When AI is configured it attempts an assessment; failure does not discard the interview. Staff can regenerate or remove the AI assessment. Scores require evidence references. Technical, problem-solving and explanation-clarity percentages are 0–5 rubric scores multiplied by 20; coding is the latest full test submission's pass rate. Missing evidence is unassessed.
8. Integrity review uses transparent multi-signal rules, never a cheating probability. Focus/visibility events are not double-counted; single events do not create a high risk rating. Monitoring does not affect technical scores or automatic selection.
9. The company or assigned HR records a human decision and explanation. Only finalized feedback can be released. Stale AI assessments must be regenerated or removed before finalization. Candidates see released feedback and their own performance history, never private monitoring or notes.
